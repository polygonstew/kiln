KILN GUIDE← back to Kiln

Kiln

A workbench for 2D pixel-art game assets: characters and their animations, parallax scenes, levels, HUDs and fonts, all saved in shapes your Godot project can use as they are. Its first rule is consistency: once something exists, everything after it should look like it belongs.

The flow, in one line

Concepts (images from anywhere) → Forge (turn into clean sprites) → Animate (frames and animations) → Scenes and Levels (the world) → HUD → Stage (try it) → Save → Godot.

Ways to get around

  • Click the KILN logo (top left) for File · Edit · View · Tools · Help. Every menu works in whatever area you're in.
  • Number keys 1–8 switch areas. Ctrl+K finds anything: areas, actions, actors, scenes, files.
  • Shift+A opens the command wheel (areas / tools / guides) at the cursor. Right-click almost anywhere for Kiln's own menu; Shift+right-click gives the browser's.
  • ? shows the keys for the area you're in. F1 opens this guide.

Into Godot: how the pipeline works

Kiln writes plain files into one asset folder. When that folder sits inside a Godot project (a folder with project.godot), every file Kiln writes uses res:// paths and Godot imports it on its own the next time you switch to it.

Set it up once

  1. File → Asset folder… and choose a folder inside your Godot project, for example <your project>/assets.
  2. The top bar's asset chip then shows Godot ✓. If it says not in Godot, saves still work, but paths are relative and you'd copy the folder into the project yourself.
  3. Save from any area. Switch to Godot: the files appear in its FileSystem dock.
Right now Kiln saves into ~/.jcodes/kiln/library/games/untitled, which is not inside a Godot project. Pallid Mask's project.godot is in its build worktree (~/.jcodes/pallidmask/.claude/worktrees/pallidmask-build); point the asset folder at that project's assets folder when you want saves to land in the game.

In Godot

  • Pixel art: Kiln sets nearest-neighbour filtering on its nodes. For new nodes, set Project Settings → Rendering → Textures → Default Texture Filter to Nearest.
  • Actors: instance sprites/<actor>/<actor>.tscn; the origin is at the feet. Call hit_flash(), squash(), shake() from your code.
  • Saving again overwrites the same files; Godot reimports them. Kiln never saves one item over another with the same name (it uses name_2).

Files 1

The asset folder as a file manager: browse, preview, rename, trash, drop files in.

  • Double-click opens; F2 renames; Delete moves to .trash (never deleted for good). Drop files from your computer to copy them in.
  • An image file: Animate from sheet cuts it into frames; right-click → Send to… sends it anywhere.
  • Change (or File → Asset folder…) points Kiln somewhere else, ideally inside your Godot project.

Concepts 8

A board per idea for pictures from anywhere: meta.ai, Gemini, a search. Works from any device that can reach Kiln (also over SSH or a phone).

  1. Click meta.ai ↗ (opens on your device). Make an image there.
  2. Copy it and Ctrl+V here, drag it in, or click the box to upload.
  3. On a card: Pixelize (to Forge), Guide (Forge guide image), Frames (cut a sheet), Actor (a whole actor with an animation set in one click).
  4. Batch → sprites turns the whole session into one consistent set: shared palette, same height, same outline.

Mask: parts that share the background's colour

Background removal takes away the colour around the figure and closed pockets of it (between the legs, inside a handle). When part of the figure is that colour too (white eyes or a white shirt on a white background), use Clean-up → Mask and paint on the source: Keep (green) is never removed, Remove (red) always is, Erase rubs mask paint out. Shift+click fills a whole area of one colour at once. ✕ clears the mask; a new source starts without one.

Animate 3

The pixel editor and animation timeline for an actor, with a live preview of how it plays.

  • Left adds, right removes, wheel rolls colours, middle picks. Tools: B E G I L R M V. O onion skin, H flip, N copy frame.
  • Box: 1 wide / 2 wide per animation gives long swings room. Red edges mean art touches the box and may be cut off in the game.
  • Animations & sheet: what the actor has, animation sets to add, and a Box template to draw into and read back.
  • Shift+click palette colours, then Colour cycle for torches, water, glow. Preview juice: F hit flash, S squash, K shake.
  • Make more frames sends the actor to Forge locked to its reference, palette and scale: new poses stay on-model.

Puppet: bones and a Flash-style timeline

Puppet (Animate tool bar) animates the actor with bones instead of drawing every frame. Rig this frame fits an 11-bone skeleton (hip, torso, head, arms, hands, legs, shins) to the frame open in Animate and colours each bone's pixels; Paint parts fixes which pixels belong to which bone, Move joints drags joints and tips, Add bone builds a skeleton piece by piece (click the joint, then the tip). Pixels a limb covered on the body are filled in from the body's colours, so moving the limb leaves no hole.

Head & mouth (right panel): the rig's heads, its own drawn head plus any you add (+ Head… from a picture, Mirror for looking the other way; a parts kit's spare heads arrive by themselves). Click a head to show it from the current frame on: it sits on the head bone, so it turns and tilts with it (the timeline's head view row). Click the big preview to place the mouth (Shift+click a swapped head's neck); Kiln draws nine pixel mouths in the head's own colours (rest, M B P, K S T EE, EH, AA, O, OO, F V, L; Mouth size sets the width). Click a mouth to show it from this frame (the mouth row). Talk without sound fills the motion with mouths opening and closing.

Voice line… (lip sync): pick a recorded line (WAV, OGG or MP3). Kiln listens to it here (loudness and where the sound sits: hums, open vowels, hiss) and makes a motion say_<line> with a mouth key wherever the shape changes and a small nod on the loud parts; Space plays it with the sound. The sound and its timings are saved beside the actor (voice/). Bake mouth set makes an animation mouths (one frame per shape): saved with it, the actor gets a LipSync node in Godot that moves the mouth in time with any of its voice lines ($LipSync.say(…), or Logic's Speak a voice line).

Import image… (or drop a picture anywhere on the Puppet screen) rigs a picture. One drawing is rigged as it is. A parts kit, a sheet of separate pieces (heads, a torso, arms, legs, hands, feet, a held prop), opens the kit screen: Kiln reads the art's own pixels, outlines each piece in the colour of what it thinks it is, and shows the assembled figure walking. Click a piece and press its label (keys 1–0) to fix a guess; spare heads and sparkles are "Not used". Pieces stacked in a column become one limb (thigh, shin, foot); a whole arm or leg is cut at the elbow or knee; one piece of a pair is used for both sides; a prop is held in the front hand. Use these parts makes the skeleton with every piece owning its own pixels. If the figure is bigger than the actor's frames, the frames grow to fit (after asking, unless the actor is still empty). Dark art is shown on a lighter checkerboard.

Pose: drag a bone's tip to turn it, the hip to move the whole body. Every change is a keyframe on the timeline below: rows are bones, columns frames; ● keyframes, grey = held, blue = motion tween to the next keyframe, with an ease from −100 (slow start) to +100 (slow finish) like Flash. F6 keyframe (Shift+F6 every bone), F7 blank keyframe, F5 insert frame, drag a keyframe to move it, double-click a cell to add or remove one, frame labels, onion skin, Space plays. Make a motion builds idle, walk, run, attack, jump, hurt or death from the rig in one click (no AI: every frame is your drawing). Bake renders the motion into an Animate animation (pixel-clean rotation); Export Godot skeleton writes the rig as Skeleton2D + Bone2D + an AnimationPlayer with every motion, for smooth in-engine animation.

Timeline: several frames at once

In the frame strip, Shift+click picks a range and Ctrl+click adds or removes one (picked frames get a yellow outline). Then Copy N frames (Ctrl+C) and Paste N (Ctrl+V) after the picked frame, in this or another animation; Delete N frames removes them. Ping-pong plays the picked frames (or the whole animation) forward and back: 1 2 3 4 becomes 1 2 3 4 3 2 1. A looping animation leaves off the last 1, because the loop starts there again.

Workshop: everything one actor needs

The Workshop button (editor tool bar) opens a checklist for the actor you have open. Pick its role (player, enemy, flyer, boss, NPC, prop) and you see every animation that role needs: missing, not posed yet (frames are still copies of the base pose) or done. Add lays an animation out, Make with Forge opens Forge locked to the actor with fitting poses, Edit jumps to it.

Status faces (like the Doom marine): healthy, hurt, badly hurt, near death, dead, grin, look left/right. Close-ups made from the reference in the actor's colours (plus blood and bruises), by the cloud (best likeness) or this PC (free). They save as faces.png + faces.json in the actor's folder.

When it gets hit: knockback and safe (invulnerable) time. In Godot, hurt(from_position) flashes, squashes, shakes, knocks the actor back, blinks while it's safe and plays its "hurt" animation.

Projectiles: + Projectile adds one with its own small animation (a starter orb to draw over) plus speed, gravity (arrows arc), lifetime, damage and pierce. Saved as projectile_<name>.tscn; in Godot shoot(direction) fires it and it calls hurt() on what it hits.

Behaviour (brains) and health

The Workshop's Behaviour card picks what drives the actor in the game: Player (platformer: run, jump higher while held, coyote time, ladders, swimming, X attacks, C shoots), Patrol (walks, turns at walls and ledges, hurts the player on touch) or Flyer (hovers, chases the player in sight). Kiln picks one from the role; the sliders set its numbers. In Godot it is a Brain node under the actor running _kiln/brains/<name>.gd: a short commented script that is yours to change (Kiln writes it once and never overwrites it).

Health (When it gets hit): hits it takes. At 0 it plays "death"; enemies vanish and the player's level restarts. The player's health drives a Kiln HUD (bar and status faces) by itself; heal(1) gives health back.

Sounds

The Workshop's Sounds card: Give it sounds makes a retro sound for each thing the actor does (jump, attack, hurt, shoot, die), made from numbers like the old sfxr. ▶ plays, 🎲 rolls another variation, the sliders change pitch, sweep, length, brightness and wave. They save as sfx_<event>.wav; in Godot the actor plays them by itself (its brain plays jump and attack, sfx("name") plays any). KILN → Tools → Sound effects… makes loose sounds (coins, doors, menus) into sfx/.

Effects

Spark, slash, dust, explosion, sparkle and ring effects, drawn by code at game size in a colour set (fire, ice, magic, blood, dust, electric); 🎲 rolls another variation. The Workshop's Effects card sets the actor's hit effect (spawned where a hit lands); each projectile can have an impact effect. Saved as one-shot scenes (vfx_hit.tscn…) that play and remove themselves. KILN → Tools → Effects… makes loose ones into vfx/.

Hit and hurt boxes

Boxes (editor tool bar) shows each frame's boxes: red hitboxes deal damage, blue hurtboxes take it. Drag to draw (pick Hitbox or Hurtbox below the canvas), right-click a box to remove it, Copy → next carries boxes to the next frame, Guess hitboxes boxes whatever sticks out past the body on every frame (a sword, a slash). Frames without a hurtbox use the body box (dashed).

In Godot the actor gets Hitbox and Hurtbox areas that follow the animation frame by frame and mirror when the sprite flips; a hitbox touching another actor's hurtbox calls its hurt(). The same boxes are in manifest.json for other engines.

In the HUD, a portrait can use an actor's status faces (Status faces → From an actor…); in Godot set_health(0.3) sets the health bar and picks the face, show_face("grin", 1.5) shows one for a moment.

Cutting a sprite sheet into frames

  • Drop a sheet on Animate (or File → Cut a sprite sheet…). Kiln reads the layout itself: file names like enemy_4x8_idle_walk_run_attack, even rows, or loose figures.
  • Even grid: drag the sheet to move the grid, drag a cell's corner square to size every cell, set Left/Top/Cell/Gap exactly, arrows nudge. Right-click a cell to skip it.
  • Custom: your own boxes. Drag to move, corner square to size, drag on empty space to add, right-click to remove; Same size for all, Align rows.
  • Untangle touching frames: when poses bleed into each other, pieces go back to the frame they belong to and joined poses are split along the emptiest seam (pink = moved, white = seam).
  • Tool bar: Erase brush (right-click restores), Clear area (drag a box), Undo. Double-click a frame to work on it up close: ◀ ▶, Clear frame, Skip frame.

Scenes 4

Parallax backgrounds from layers: generated, described in words, or your own images.

  • Layers are ordered back to front; the depth ruler shows each one's scroll speed. A warning offers Sort by depth when the order fights the speeds.
  • Drag to reorder, Alt+click an eye to solo, H hide, Ctrl+D duplicate, Delete delete, Ctrl+Z undo.
  • Per layer: opacity, blend (Glow for fire and windows), tint, own haze, Reroll with ◀ ▶ history. Generators include Ground (cobbles, roots, rubble, puddles) and Foreground silhouettes.
  • Weather: rain, snow, embers, mist (exported as Godot particles). Review: Show safe frame / HUD, Time night↔day, snapshot, Record pan.
  • Layer → Tiles for Levels cuts it into a tileset.

Levels 7

Rooms painted from tiles, with collision, a background scene, actors and a player start.

  • Paint → Tiles: left paints, right erases, wheel rolls tiles, middle picks. Shift+click a tile in the set to make it solid.
  • Tool bar (above the map): Brush B (size 1–3, [ ]), Rectangle R, Line L, Fill G (the connected area of one tile), Pick I, Select M. With a selection: Copy / Cut (Ctrl+C/X), then click to stamp it as often as you like (Esc stops), or Clear (Delete). Right click always erases. Ctrl+Z / Ctrl+Y undo and redo tiles, things and zones; Clear (next to Size) empties the level. Space+drag pans, + / − zoom.
  • Tile N is (under the tiles): what the picked tile does in the game. Solid walls and floors, One-way platforms (jump up through), Slope ◢ ◣ ramps, Ladder, Hazard (spikes, lava: hurts any Kiln actor touching it), Water. Show behaviours draws them over the map.
  • In Godot the TileSet carries each tile's collision and a kind; the level's TileMapLayer runs _kiln/level_tiles.gd: kind_at(position) tells your player code it is on a ladder or in water, and hazards call hurt() by themselves.
  • Autotile (under the tiles): pick a tile, choose Grass top, Lit top edge or Outline only, press From tile N. Kiln builds the 16 pieces a platform needs (caps, edges, corners) into the tileset; paint with ▦ name and every tile picks the right piece from its neighbours (erasing re-joins them too). Godot gets the same set as a terrain, so its terrain painter continues where Kiln left off.
  • Paint → Zones: drag a rectangle on the map (it snaps to tiles), click one to edit, right-click removes. Checkpoint remembers the spot, Door goes to another level, Message shows text in the HUD's dialogue box, Deadly (pits) hurts the player and puts it back at the last checkpoint, Event only signals your code. In Godot each is an Area2D running _kiln/zone.gd; every zone emits triggered(name, body). The player is the actor whose Workshop role is Player (Godot group player).
  • Paint → Things: place the ⚑ player start and any saved actor (feet on the tile top).
  • Background: a saved scene drawn behind the map and placed behind it in Godot.

Play: a test build of your game

▶ Play (top bar) builds a small game from your asset folder with Godot and plays it in the Stage: the level you pick with the player actor (the one whose Workshop role is Player), a camera that follows it, and your HUD. No level yet? You get a long floor in front of a scene. The build is a copy in kiln/build/: your files are only read. The last build stays at /play/.

Menus: title, options, pause

The Menus area (key 0) makes the game's title menu, options (volume sliders for all sound, music and effects, fullscreen, on/off options like screen shake, the list of controls) and pause menu. Each screen: a title, a scene or colour behind it, dim, text size, colours, and a list of items, each a button with an action (start, open options, back, resume, quit to title, quit) or a setting. The preview is at game size.

Save menus writes menus/title.tscn, options.tscn, pause.tscn, kiln_menu.gd (builds a screen from its items and emits action(name)) and kiln_settings.gd (KilnSettings.volume("Music"), KilnSettings.flag("screen_shake"), saved for the player). ▶ Play uses them: the title menu first, Esc pauses.

Tours

Every area has a short tour: speech bubbles that point at each part in turn. Start it with Shift+F1, KILN → Help → Tour this area, or right-click → Help. →/Enter next, ← back, Esc ends it. The first time you open an area, Kiln offers its tour once.

History: earlier versions

Every time an actor, scene, level or HUD is saved, Kiln keeps the version it replaces in kiln/history/: at most one every 10 minutes, the newest 5 of each, 1 GB in all. KILN menu → File → History…: pick an item, pick a time, Restore as copy. The old version comes back as a new item named with its date (open it from that area's Open); the current one is never touched.

Doctor: check the asset folder

KILN → Tools → Doctor… looks through the asset folder and lists what is wrong or odd: problems (a scene needs a file that is not there), worth fixing (sprites far bigger than game size, more colours than a retro sprite had) and good to know (loose images, items only Kiln has, very heavy project files). Each line has a fix or a Show.

Game-size copy (also in Animate when an actor is over 128 px): every frame shrunk by the same amount (area-averaged, then cleaned of stray pixels) onto one 15-colour palette shared by all frames. It is a copy; the big one stays as it is.

Logic: graphs and scripts

Graphs: game logic without code

A graph is events wired to actions. New graph starts empty or from an example (a line after a second, a score from zones, waves of enemies, a locked door that needs a key). Nodes come in four colours: events start a chain (the level starts, every frame, a key, the player enters a zone, every few seconds, someone dies, the player is hit, a message arrives), flow steers it (if, wait, repeat, only the first time, sometimes, at most every…), actions do things (say a line, speak a recorded voice line with lip sync, show a prompt, set HUD bars and counters, set and add to variables, heal, hurt, shake, play an animation, move the player to a zone, spawn an actor, play a sound, give an item, send a message, game speed, restart) and values feed inputs (numbers, text, variables, the player's health and position, random numbers, maths, comparisons, and/or, key held, has an item, level is).

  • Wiring: drag from a port to another. White triangles carry the chain (what happens next); round ports carry values, coloured by kind (green numbers, pink text, red yes/no, grey anything). Drop a wire on empty board and a menu shows only the nodes that fit; pick one and it is wired in. Drag a wired input to pick its wire up; drop it on nothing to remove it.
  • The board: drag to pan, wheel to zoom, F shows everything, Shift+drag selects, Ctrl+C/V/D copy, paste, duplicate, Del deletes, Ctrl+Z/Y, A or right-click / double-click adds a node. The right panel lists every node too.
  • Variables (right): values the graph remembers while the game runs: whole numbers, numbers, text, yes/no, each with a starting value.
  • Its script: the graph as plain GDScript, live while you work: one function per event, short helpers only when used. Save writes logic/<name>.gd and Godot checks it. ▶ Play runs every graph; in your own Godot project put the script on a Node in the level (or make it an Autoload). Make it my script copies it into scripts/ to go on by hand.

Scripts

Every .gd in the asset folder in one list: Brains (actor behaviours, yours to change), Kiln's scripts (_kiln/: rewritten when Kiln saves, so changes there do not last), HUD scripts and your scripts (scripts/). New script starts an empty one or a copy of a brain.

  • The editor: colours for GDScript, line numbers, Tab/Shift+Tab indent (Godot uses tabs), Enter keeps the indent (one more after a :), Ctrl+/ comments lines, Ctrl+S saves.
  • Godot checks every save (the real Godot on this machine, --check-only): problems are listed on the right with their line, marked red by the line numbers; click one to jump to it.
  • Kiln reference: what Kiln's scripts give you (hurt, heal, shoot, kind_at, set_health, say…). Click a line to insert it at the cursor. Outline: the script's functions and settings; click one to jump to it.

HUD 5

Everything on screen during play: health bars, gauges, pips, counters, text, panels, slots, portraits, an inventory, a dialogue box and button prompts, plus bitmap fonts. It saves as a real Godot scene.

  • Drag widgets; arrows nudge (Shift: 8 px); Ctrl+D duplicates; Play values animates everything (bars move, dialogue types, the inventory cursor walks).
  • Inventory: columns, rows, slot size, frame styles; + Item adds items with an icon (any saved actor's first frame), name, description and count.
  • Dialogue: a face, the speaker's name and the line; Prompt: a key cap and an action ("E Open").

In Godot

Save writes hud/<name>/<name>.tscn (a CanvasLayer of real nodes: TextureProgressBar, NinePatchRect, Labels using Kiln's bitmap fonts) and hud.gd. Add the scene to your game and call:

Set the Godot window to the HUD's screen size (e.g. 480×270, stretch mode "viewport") so the pixels stay crisp.

Stage 6

The playtest room: your real game, built by Godot from the asset folder, running right here, with the player's numbers on sliders.

  • In the game: the level, player, HUD (and a background when there is no level) that go into the build, and what it starts with (straight into the level, a plain title screen, or your title menu from Menus). ↗ opens that thing in its area to fix it. After changes here or saving elsewhere, Rebuild (it shows • when the build is out of date). A build takes 10 s to a minute; your files are only read.
  • Tune the player: run speed, jump height, time to the top of a jump (floatiness), coyote time, health, knockback and safe time after a hit. They change the game while you play, no rebuild. Nothing is saved until Keep in <actor>, which writes them into the actor's Workshop settings and saves it; Reset goes back to the saved numbers.
  • Click the game for the keys: arrows move, Space jumps (hold for higher), X attacks, C shoots, Esc pauses (with a pause menu). Restart starts over without rebuilding, Screenshot saves a PNG at 3×, Record saves a WebM video (up to 30 s), Open in a tab plays it on its own.
  • Below the game: the build log and the game's own output (errors in red). The game stops while you are in another area.
  • Browsers only run Godot web games on a secure page (https, or http on the machine itself). On Kiln's plain LAN address the Stage shows a button to Kiln's https address instead (Tailscale serves it with a real certificate, to your own devices only); everything in Kiln works there.

In Godot: the build's main.gd reads the Stage's numbers through JavaScriptBridge (web builds only) and sets them on the player's Brain and juice.gd; the player brain's retune() works out gravity and jump speed again.

The Kiln plugin for Godot

A Kiln dock inside the Godot editor (top right). It talks to Kiln over the network, so Kiln keeps running as it is.

  • Install: in Kiln, Tools → Godot plugin…. If your asset folder is inside a Godot project it installs and switches itself on; otherwise you get a zip to unzip into the project (it makes addons/kiln), then Project Settings → Plugins → Kiln → On.
  • Check shows whether Kiln is running and where it saves. Link here makes Kiln save straight into this project (res://assets, changeable in Project Settings → kiln/assets_dir).
  • The list shows the actors, scenes, levels and HUDs Kiln has saved: double-click opens one, + adds it to the open scene (undoable). Rescan picks up new saves; Open Kiln opens it in the browser.

Generators and budget

  • Cloud uses a free daily quota first (Cloudflare, resets 8 PM), then a paid backup capped at $2 total. The Cloud button shows what's left.
  • Fast (local) loads on first use and frees its memory after 15 idle minutes. ComfyUI models (Sprite, Painted, Scene) are slower but free.
  • A Downloads inbox: images saved to Downloads or a concept folder show up in Forge's Generated tray as "new".

Your work is safe

  • Two things never share a name: a new actor/scene/level/HUD that clashes is saved as name_2.
  • Opening something never writes it back; only changes save. Deleting in Files moves to .trash.
  • Undo: Animate and Scenes (Ctrl+Z), the sheet cutter's erasing.
